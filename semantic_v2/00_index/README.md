## Project-wide method consistency

The same calculation architecture must serve:

```text
ordinary concrete + reinforcement
ordinary concrete + steel shell
UHPC + reinforcement
UHPC + steel shell
```

A specimen or steel-phase type may not trigger a bespoke material compiler, structural integration method, root topology or error-tuned solver.

## Compiler-order governance

The project is not hard-locked to N48. The 11:31 N48 hard lock is superseded.

```text
POLYNOMIAL_ORDER_IS_NOT_A_THEORY_IDENTITY
CASE_BY_CASE_MANUAL_ORDER_TUNING = PROHIBITED
SAME_COMPILER_ARCHITECTURE = REQUIRED
SAME_SOURCE_FIDELITY_CONTRACT = REQUIRED
SAME_ORDER_SELECTION_ALGORITHM = REQUIRED
SAME_MATERIAL_DOMAIN_POLICY = REQUIRED
```

The numerical algebraic order must be selected by one deterministic source-only convergence procedure. Once frozen for a material family/domain, it is reused across all specimens and both rebar/shell variants of that material family.

Hence:

```text
NC+rebar and NC+shell -> one frozen NC compiler
UHPC+rebar and UHPC+shell -> one frozen UHPC compiler
```

Different material families may converge at different numerical orders because their physical source operators differ; this does not constitute a different calculation method.
