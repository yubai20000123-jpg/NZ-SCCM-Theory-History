## 1. Governing principle

The project shall use **one production workflow contract**, not one bespoke method per specimen.

The four target combinations are:

1. ordinary concrete (NC) + reinforcement;
2. ordinary concrete (NC) + steel shell;
3. UHPC + reinforcement;
4. UHPC + steel shell.

A specimen type may activate a different physical adapter when the physics genuinely differs, but the following project-level mechanics and numerical-governance identities are common and may not be changed case by case.

## 3. Common production state

At minimum every production run exposes the same global variables

\[
\boxed{g=(D,q)}
\]

with

\[
A=qb,
\]

plus any **finite internal coordinates** required by the specimen physics, for example local steel-shell buckling amplitudes

\[
\mathbf a=(A_1,\ldots,A_n).
\]

Internal coordinates are allowed only when a source-grounded structural mechanism requires them. They are not spatial material points or hidden mesh degrees of freedom.

## 4. Common resultant / residual / limit contract

Every material/structural phase adapter must return finite analytic contributions to

\[
P=\sum_pP_p,
\qquad
R_q=\sum_pR_{q,p},
\]

and consistent derivatives

\[
P_D,\ P_q,\ R_{q,D},\ R_{q,q}.
\]

Without internal coordinates, the primary limit determinant is

\[
\boxed{L=P_D R_{q,q}-P_qR_{q,D}}.
\]

The production capacity candidate is the first admissible connected-branch solution satisfying

\[
R_q=0,\qquad L=0,
\]

with a genuine `+ -> -` load maximum on the connected physical branch.

No Zhou/Winter/experimental value may choose the root.

## 5. Internal-coordinate extension is type-specific but algebraically unified

If a physical adapter introduces finite internal coordinates \(\mathbf a\), solve

\[
\mathbf R_a(D,q,\mathbf a)=0.
\]

With

\[
\mathbf J_{aa}=\partial\mathbf R_a/\partial\mathbf a,
\]

implicit differentiation gives

\[
\mathbf a_{,g}=-\mathbf J_{aa}^{-1}\mathbf R_{a,g}.
\]

Then use exactly condensed derivatives

\[
\widetilde P_{,g}=P_{,g}+P_{,a}\mathbf a_{,g},
\]

\[
\widetilde R_{q,g}=R_{q,g}+R_{q,a}\mathbf a_{,g},
\]

and

\[
\boxed{\widetilde L=\widetilde P_D\widetilde R_{q,q}-\widetilde P_q\widetilde R_{q,D}}.
\]

This is the common extension mechanism for source-grounded finite internal structural variables. It is not a new specimen-specific root theory.

## 6. Common tangent-stability contract

Each phase contributes

\[
K_Z=\sum_p\left(K_{Z,p}^{mat}+K_{Z,p}^{geo}\right),
\]

where the material part uses the **consistent current tangent** and the geometric part uses the **same current stress field**.

If finite internal coordinates are active, the global current tangent is exactly condensed:

\[
\boxed{
K_{gg}^{cond}=K_{gg}-K_{ga}K_{aa}^{-1}K_{ag}
}.
\]

The tangent/stability calculation is an audit/control condition on the same branch and same state. It does not replace the primary `P,Rq,L` capacity root with a second unrelated Pu solver.

## 7. Allowed type adapters

### 7.1 NC material adapter

```text
SOURCE_OPERATOR = frozen R10
MATERIAL_COMPILER = NC-family compiler frozen by source-only fidelity/convergence rule
```

The same frozen NC material compiler is reused for NC+rebar and NC+steel-shell.

### 7.2 UHPC material adapter

```text
SOURCE_OPERATOR = future source-frozen multidimensional UHPC current operator
MATERIAL_COMPILER = UHPC-family compiler generated by the same fidelity/convergence governance
```

UHPC is allowed different physical formulas, parameters, basis details and converged algebraic order because it is a different material family. It is not allowed a different structural integration/root philosophy.

### 7.3 Reinforcement adapter

Reinforcement contributes exact directional strain/resultant/tangent terms. It does not alter the concrete/UHPC material compiler, Nguyen kinematics, D15 engine or root topology.

### 7.4 Steel-shell adapter

The shell contributes finite-thickness current stress/resultant/tangent terms and, where source-grounded local buckling is active, finite local amplitudes handled by the exact condensation contract above. Through-thickness spatial quadrature remains zero.

### 7.5 Boundary / halfwave adapter

Boundary conditions and halfwave selection may differ only because the real specimen/source design boundary differs. The method remains: declare the physical boundary before the solve and determine admissible halfwave(s) from the theoretical/design energy/boundary rule, never from the measured failure load or observed target mode.

## 8. Material compiler governance

The project is not hard-locked to `N=48`.

However:

```text
CASE_BY_CASE_MANUAL_ORDER_TUNING = PROHIBITED
CASE_ID_IN_COMPILER_OBJECTIVE = PROHIBITED
STRUCTURAL_Pu_IN_COMPILER_OBJECTIVE = PROHIBITED
EXPERIMENT_IN_COMPILER_OBJECTIVE = PROHIBITED
```

Compiler implementation may differ by **material family** if required by the source material structure, but every family must satisfy the same interface:

```text
source current operator
-> finite analytic representation
-> source-value fidelity audit
-> source-tangent fidelity audit
-> deterministic convergence/order/domain rule
-> frozen family compiler
-> same matrix lift + D15 structural backend
```

Once frozen, the family compiler is reused unchanged across all specimens using that material family. If a later specimen exits the frozen material domain, the family domain is enlarged and the family is recompiled consistently; a one-off specimen compiler is forbidden.
